## Design (agent-owned, within scope; no backend contract change)

- D1 Durable local marker `LocalProfileSnapshot.AdmissionPendingReservationId` (schema 13 -> 14, gated read; older caches decode with no marker). Set atomically with the local admission confirm (`LocalProfileStore.TryAdmitLoadoutReservation`), cleared only on backend proof: admit success (idempotent for an already-admitted id) or login hydration showing the backend no longer holds that reservation.
- D2 `ReservationAdmissionRetry`: outer bounded rounds with progressive pauses (`BackendRetrySchedule`) over the existing 3-attempt `RemoteIdempotentRetryPolicy`; stops on success or terminal error; the marker survives exhaustion so login retries.
- D3 Rollback guard: the store refuses to roll back (and `RemoteInventoryService` refuses to send a backend rollback for) the reservation id held by the marker.
- D4 Login: an un-admitted backend reservation matching the marker is resolved as a loss (local discard, never restore), re-sends the idempotent admit and then clears it on the backend as a loss; on failure the marker stays and the next login retries.
