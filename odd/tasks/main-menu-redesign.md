# Main menu redesign — production integration

Bring the chosen artboard `design/main-menu/01-centered-modal.html` (incl. its "Implementation notes" panel) into `Project Grimhold/Assets/Scenes/MainMenu.unity`, skinned like the isolated preview `Assets/Scenes/Previews/MainMenuDesignPreview.unity`, and wired to existing logic.
Functional source: live Game Design "UI - Auditoría Funcional de Interfaces MVP" §4 (Main Menu). No commits without explicit authorization (repo rule).

## Specs

- **S1 — No preview chrome.** "toda la barra inferior de preview es innecesaria en el main menu". The MainMenu scene has no PREVIEW state toolbar, no "UI PREVIEW · No network or credentials stored" notice, and no hardcoded/fake server or account states.
- **S2 — Artboard layout.** "hay que llevar el resto del diseño a la escena main menu". Composition of artboard 01: title; primary Play button with a subtitle line; divider; Settings, Credits, Exit; server status chip top-left; account chip top-right (state + Sign in/Sign out action); version label bottom-left; keyboard hints bottom-right; status line under Play; auth dialog over the menu (tabs Sign in / Create account, Step 1 of 2 · Account, Step 2 of 2 · Character); confirmation dialog; info dialog.
- **S3 — Incumbent visual identity.** "quiero usar los mismos assets y fuentes que estaba usando". Same mapping as the preview restyle (`design/main-menu/RestyleUnityPreview.cs`): Charcoal atlas `Art/UI/Charcoal/grimhold-ui-charcoal.png` sprites `button_normal` / `panel_main` / `input_normal`, with the original Sprite Swap states (button highlighted/pressed/selected/disabled, input focused); Alagard SDF for menu and form text as in the original prefabs; original black camera background. No new art, fonts or dependencies.
- **S4 — Language.** Decision: "Español". All player-visible text is Spanish, consistent with the existing labels ("Jugar", "Iniciar sesión", "Registrarse").
- **S5 — Logic wiring.** "hacer las conexiones necesarias con la logica". Play enters Town through the existing `CreateRoom()` / `SessionConnectionCoordinator` when authenticated, otherwise opens Sign in. Settings and Credits open the existing `SettingsPanelView` / `CreditsPanelView`. Exit asks for confirmation, then calls `QuitAction`. Account chip Sign in opens the auth dialog; Sign out asks for confirmation, then `LoginFlowController.ExecuteLogoutAsync`. Login, register and character creation use `LoginFlowController` as today. Busy state blocks actions as today. A failed Town entry shows the error plus a Retry action. `ApplicationAuthContext.SessionInvalidated` shows a notice that the session ended and refreshes the account chip.
- **S6 — Remember username only.** Decision: "Recordar solo el usuario (Recomendado)". A checkbox labeled as remembering the username (it must not promise keeping the session) stores only the username locally when checked, prefills it when the sign-in form opens, and clears it when unchecked. The password, token or any secret is never written to disk. No backend or auth-contract change.
- **S7 — After login.** Decision: "Entrar directo al Town". After successful sign-in or character creation, Town entry starts automatically (current `HandleLoginFlowResult` → `CreateRoom()` behavior preserved).
- **S8 — Form UX.** From the artboard: separate Sign in / Create account tabs; Create account adds Confirm password; Show/Hide password toggle; Caps Lock warning; per-field validation mirroring backend register rules (username 3–20 letters, numbers and spaces; password ≥ 6 characters; passwords match) and per-field mapping of backend errors (`USERNAME_TAKEN`, `VALIDATION_FAILED` `details[].field`, `INVALID_CREDENTIALS`); distinct messages for wrong credentials, server unreachable, and too many attempts (countdown from the rate limiter's retry-after, submit disabled meanwhile); Enter submits, Esc goes back; "Forgot password?" opens an info dialog explaining recovery is not available yet (accounts have no email).
- **S9 — Server status.** Chip reflects backend `GET /health`: online / unreachable with Retry; Play is disabled while unreachable, with the reason shown on Play's subtitle.
- **S10 — Character step.** Character creation is "Step 2 of 2 · Character" inside the same dialog, with "Sign out and finish later" (signs out; next sign-in resumes at this step via `NeedsCharacterCreation`).
- **Out of scope:** persistent session / session restore at boot, password recovery backend, "Update required" (auth endpoints do not emit `CLIENT_UPGRADE_REQUIRED`), dev room-code join UI (stays hidden as today), Settings/Credits panel contents.
