# Gameplay camera (TASK-222)

Execution tracker for HacknPlan TASK-222 (work item 574, Sprint 18) "Implementar la cámara de gameplay según Player Design".
Scope authority: HacknPlan item; behavior authority: live GD 03 - Player Design §8 and §11. This file records execution, not backlog.

## Specs

- S1: "Al mover el cursor alrededor del jugador, la cámara se desplaza hacia él y nunca supera la distancia máxima configurada."
- S2: "En ningún caso el jugador queda fuera del área visible segura."
- S3: "Cerca de un borde del mapa, la cámara no muestra nada fuera del mapa, en Pueblo y en Dungeon." Scope: "Los límites se configuran por escena. Si el mapa es más chico que la vista en un eje, se centra en ese eje."
- S4: "Distancia máxima, velocidad de seguimiento, suavizado y tamaño ortográfico se cambian desde el asset de configuración y se aplican en Play Mode sin recompilar."
- S5: "En espectador, la cámara sigue al compañero observado con el mismo comportamiento de seguimiento y límites."
- S6: "Con el inventario abierto, mover el mouse no desplaza la cámara." Scope: "mientras una UI bloquea el input de gameplay (inventario, contenedor, comercio), el offset por cursor se congela o vuelve a cero".
- S7: "El shake sigue funcionando."
- S8: "La cámara es local: no se replica y no cambia la simulación de red."
- S9: "Se agregan tests de la matemática pura (clamp del offset, clamp a los límites, centrado con mapa chico)."
- S10: "Cambiar de objetivo (spawn o espectador) no produce saltos raros: se mantiene el snap inicial existente."

- S11 (user, L12): "esta demasiado sensible" — cursor offset must ramp proportionally across the whole screen (cursor at screen edge = max distance) with a configurable central dead zone, instead of saturating near the screen center.
- S12 (user, L12, L14): "deberiamos agregar tambien esos ajustes en settings para poder calibrar a gusto" / "igual los parametros tambien tienen que ser editables, mas alla de que el usuario pueda ajustar. El zoom es algo que no quiero que el jugador pueda cambiar." — player Settings exposes offset intensity (max distance), smoothing and follow speed only; persisted locally (PlayerPrefs) as optional overrides over `GameplayCameraConfig`, clamped to designer-owned ranges in the config, applied live, with reset to defaults. All parameters (including orthographic size, dead zone, safe margin and the ranges) stay editable in the config asset and apply live; orthographic size (zoom) has no player override.

- S13 (user, L17): "con cualquier interfaz abierta no deberia moverse la camara" — every blocking player-facing interface holds a gameplay-input suppression while open (so the cursor offset eases back to zero and stays still). Gaps found: Mission board (`MissionBoardUI`), Town raid-loss notice (`TownRaidLossNoticePresenter`). Opening a UI keeps the current smooth return to zero (no freeze).

Out of scope (HacknPlan): manual zoom, gamepad right-stick offset, pixel-perfect camera.
