# Audio system fixes

Execution tracker for the audio audit follow-up (Unity project `Project Grimhold/`, branch `New-Testing`).
Scope comes from the audit findings and plan the user approved (see Log L1-L4). No HacknPlan item; commits require explicit user authorization.

## Specs

- S1 (D1, L2): "d1: si." -> other players (observers) must hear the impact of another player's weapon hit, not only the attacker.
- S2 (D2, L2): "la ui y la musica supongo que son 2d. lo demas seria 3d, los sfx afectan al gameplay." Approved rule (L3/L4): UI, music and global warnings (dungeon pressure phase cues) are 2D; everything happening in the world is 3D. 3D distance must depend only on gameplay X/Y (listener camera sits at z = -10, which today attenuates every 3D sound by about -20 dB); min/max distance and rolloff are configured in one place on `AudioManager`, tunable in the Inspector (default audible up to about 20 units).
- S3 (D3, L3/L4): the `AudioManager` prefab is placed in every entry scene and an EditMode test requires it; the existing duplicate-destroying singleton keeps the first instance. No global bootstrap.
- S4 (D4/D5, L2/L4): "D4: todavia no hay audio para este personaje. D5: misma respuesta que D4." and "salvo que los sonidos del espectro usamos cualquier placeholder y despues toca cambiar cuando ya tengamos los audios." -> Specter sounds use any existing placeholder clips, replaceable later by only editing the ScriptableObject. Keys without content (`Death`, `Charge`, `Cast`, bomb/smoke sounds, ranged `Block`) are declared optional: silent until clips are added to the ScriptableObject, no code change needed. Local crack warning stays blocked by content.
- S5 (L3): audio sets remain ScriptableObjects (`EntityAudioConfig` key -> `CustomClip`); no structural change or migration of existing audio assets. `CustomClip` "volume 0 = 1" semantics are not changed.
- S6 (audit, approved plan): enemy prefabs `NetworkEnemy` (melee/Slime, to confirm) and `NetworkEnemySpecter` have `EnemyAudioPresenter._audioConfig = null`; every prefab with an audio presenter must reference a config.
- S7 (audit, approved plan): `PlayerAudioPresenter`/`EnemyAudioPresenter` health observation: `Death` once per death, no false `TakeDamage` on revive or when `AudioManager` appears late, a second death after revive plays again, multiple hits per frame do not crash, invalid/despawned objects are not read.
- S8 (audit, approved plan): all audio goes through the mixer: `DungeonDoor` and `PlayerStatusFeedback` AudioSources use the SFX group; no `AudioSource.PlayClipAtPoint` in `Assets/Scripts` (bomb, smoke, `RuneCompassPointerEffect`, `PlayerInventoryPassiveEffectsController`).
- S9 (audit, approved plan): audio keys are centralized constants; footstep key unified to `Step` (code used `Movement`); an EditMode validation fails when a required key is missing from an assigned config.
- S10 (audit, approved plan): cleanup: remove unused `AudioClipConfig`; dedupe `CombatFeedbackResolved` by sequence; pool steal policy steals the oldest playing source.
- S11 (audit, approved plan): bomb/smoke detonation effects must not rely on an RPC sent in the same tick as `Runner.Despawn`.
- S12 (L15): "el esqueleto en si no tiene nada que recargar ya que su ataque es el lanzamiento de huesos con las manos, no se si deberia tener un sonido de recarga" -> enemies have no reload mechanic, so the enemy `Reload` cue (fixed 0.25 s coroutine in EnemyAudioPresenter) is removed, together with the Skeleton config `Reload` entry and the Enemy optional `Reload` key. Player weapon reload audio is unchanged.
- S13 (audit, approved plan): tests for `PlayerAudioPresenter`, `EnemyAudioPresenter` and both animation listeners; `WeaponAudioPresenterTests` without reflection on private fields where a seam exists.
- S15 (L25): "al salir de town el clip de musica sigue, se escucha en la pantalla de carga y se sigue escuchando en la raid" -> a scene's music stops when that scene unloads; music started later by something else (e.g. collapse music) is kept.
- S16 (L26): "sigue sin sonar la musica de la raid" -> the Raid scene (CatacombsMap) plays the `Raid` track.
- S14 (audit, approved plan): `Docs/Architecture/AudioArchitecture.md` updated with each change (reload via replicated state, Charge/Cast/Attack->Hit, 2D/3D policy, bootstrap, mixer rule, optional keys).
